# مواصفات المنتج وتجربة واجهة SOC

**الحالة:** مواصفة أولية قابلة للتعديل بعد توضيح أنواع المصادر وحجم البيئة.

## 1. اللغة البصرية

- واجهة ويب احترافية داكنة، مناسبة للعمل الطويل، مع تباين واضح وقراءة سهلة.
- أساس لوني slate/graphite، وألوان الحالة تستخدم للدلالة فقط: أحمر للخطر، برتقالي للتحذير، أزرق للمعلومة، وأخضر للصحة.
- كثافة معلومات جيدة دون تكديس بطاقات KPI بلا معنى.
- جدول الأحداث هو العنصر العملي الرئيسي، مع أعمدة قابلة للفرز وإخفاء/إظهار.
- كل الرسم البياني يمكن الانتقال منه إلى الأحداث التي كوّنته؛ لا رسوم لا تسمح بالتحقيق.
- يدعم العربية والإنجليزية وRTL/LTR على مستوى التخطيط، لا بمجرد قلب محاذاة النص.
- Responsive: شاشة مكتبية واسعة للتحقيق، وشاشة أصغر للمتابعة والتنبيه.

## 2. تخطيط الهيكل

### الشريط الجانبي

### الشريط العلوي

- اختيار نطاق الزمن.
- اختيار Tenant / Environment.
- بحث عام عن IP أو Host أو User أو Alert ID.
- حالة الاتصال ومصدر البيانات.
- الإشعارات وملف المحلل.

### Overview

يُظهر:
- Events per second والـ ingestion delay.
- حالة كل Sensor وعدد المصادر الصامتة.
- التنبيهات حسب الخطورة وحالة الإقرار.
- أهم الأصول والحسابات ذات المخاطر.
- Top detection rules مع عدد التطابقات ونسبة الضجيج.
- Timeline للتهديدات خلال الفترة.
- Blind spots التي تقلل موثوقية الرؤية.

### Live Events

جدول حي:
- وقت الحدث، المصدر، الفئة، الإجراء، المضيف، المستخدم، IPs، الخطورة.
- فلاتر سريعة ومحفوظة.
- فتح التفاصيل الخام والمطبّعة معاً.
- عرض سبب التطبيع وإصدار المحول.
- منع عرض payloads الحساسة افتراضياً، مع صلاحيات للوصول المقيد.

### Alerts Queue

- قائمة موحدة مع Critical/High/Medium/Low.
- حالة New/Acknowledged/Investigating/Resolved/False Positive.
- المحلل المسؤول ووقت الاستجابة.
- Deduplication يظهر كم مرة حدثت الإشارة.
- عرض الأدلة والقواعد والـ ATT&CK references.

### Investigation Workspace

- Timeline قابلة للتصفية.
- Behavioral Episode Graph للعلاقات.
- عرض User / Host / IP / Process / Session ككيانات.
- قائمة الأحداث الداعمة لكل علاقة.
- Notes وTasks وEvidence references.
- سجل تغييرات للحالة والقرار.
- زر "لماذا ربط النظام هذه الأحداث؟" يشرح قاعدة الارتباط.

### Detection Center

- قائمة القواعد وإصداراتها وحالتها.
- محرر قواعد مع validation.
- اختبار العينة وإعادة تشغيل بيانات محفوظة.
- الحقول المطلوبة لكل قاعدة.
- ربط ATT&CK وData components.
- قياس عدد التطابقات والضجيج والتغيّر بين الإصدارات.

### Assets & Sensors

- Inventory للأصول والمصادر المعتمدة.
- آخر اتصال ومعدل الأحداث.
- التغطية والمكونات/الحقول المتاحة.
- إصدار Connector وحالة التحديث.
- فجوات الجمع وسببها.
- لا يظهر جهاز على أنه آمن لمجرد أنه لم يرسل تنبيهاً.

## 3. مبدأ العرض

كل رقم أو لون أو درجة خطورة يجب أن يجيب عن سؤال المحلل. يجب أن يستطيع المحلل الانتقال من KPI إلى مجموعة الأحداث التي أنتجته، ثم إلى التنبيه، ثم إلى الحالة. لا نستخدم مؤشرات وهمية أو بيانات Demo على أنها بيانات حقيقية.

## 4. أفكار واجهة مميزة

### Explainable Alert Card
تظهر:
- What happened
- Why it fired
- Evidence events
- Entity context
- ATT&CK mapping and mapping version
- Confidence factors
- Missing telemetry / limitations
- Next recommended defensive checks

### Blind-Spot Banner
إن كانت أحداث تسجيل الدخول متوقفة أو المستشعر فقد اتصاله، تعرض الواجهة فجوة الرؤية بدلاً من عبارة "No threats".

### Rule Replay Comparison
عند تعديل قاعدة، يرى المحلل قبل/بعد: ما الأحداث التي أصبحت تطابق، وما الأحداث التي توقفت عن المطابقة، ولماذا تغيرت النتيجة.

### Episode Timeline
تجمع الأحداث حسب كيان وزمن، مع إظهار العلاقات المؤكدة والمرجحة بشكل مختلف، وعدم تحويل الارتباط الزمني إلى ادعاء سببي قطعي.

## 5. حدود الإصدار الحالي

هذه المواصفات ليست واجهة منجزة. الإصدار الحالي يقدم API أساسية وبيانات أحداث وتنبيه أولي. بناء الواجهة سيبدأ بعد استقرار عقود API والتخزين والصلاحيات، حتى لا تكون الواجهة مبنية على بيانات تجريبية أو endpoints مؤقتة.
