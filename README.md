# نظام المراقبة المرورية والأمنية الذكي

**Cyber Surveillance System** منصة مركزية قيد البناء باستخدام Python والرؤية الحاسوبية، هدفها مراقبة الطرق والمناطق والمنشآت عبر كاميرات متعددة وتحويل الفيديو إلى تحليلات وأحداث قابلة للفهم والتحقيق.

> هذا المشروع ليس SIEM ولا برنامج حماية أجهزة أو Endpoint Security. نطاقه هو **المراقبة المرئية المرورية والأمنية** بالكاميرات، مع تحليلات حركة المركبات والأشخاص والأحداث الميدانية.

## ما الذي نبنيه؟

### المراقبة المرورية
- كشف وتصنيف المركبات والمشاة.
- تتبع الكائنات عبر الإطارات وإحصاء التدفق حسب المسار والاتجاه.
- قياس السرعة بعد معايرة هندسية لكل كاميرا.
- كشف تجاوز السرعة، السير عكس الاتجاه، التوقف غير الطبيعي، عبور الخطوط، والوقوف داخل مناطق ممنوعة.
- تقدير الازدحام وطول الطوابير ومؤشرات الانسداد.
- لاحقاً: قراءة لوحات المركبات في مصادر مصرح بها، مع ضوابط خصوصية واحتفاظ واضحة.

### المراقبة الأمنية المرئية
- دخول مناطق محظورة وتجاوز محيط افتراضي.
- التسكع أو البقاء غير المعتاد داخل منطقة.
- اكتشاف التجمعات أو الأجسام المتروكة عند توافر نموذج مناسب.
- اكتشاف أحداث مرورية خطرة مرشحة مثل تعارض مسار مركبة ومشاة أو توقف مفاجئ، على أنها مؤشرات تحتاج مراجعة بشرية.
- حفظ لقطات ومقاطع مرتبطة بالأحداث.

### مركز التحكم
- جدار كاميرات متعدد البثوث.
- قائمة أحداث وإنذارات مرتبة حسب الأولوية.
- معايرة كل كاميرا ومناطقها وخطوطها وقواعدها.
- بحث زمني ومراجعة مقاطع الأدلة.
- صحة الكاميرات وجودة البث وفجوات الرؤية.
- خرائط مواقع اختيارية عندما تكون إحداثيات الكاميرات متاحة.

## الحالة البرمجية الحالية

- نواة هندسية لتصحيح المنظور وتحويل إحداثيات الصورة إلى مستوى الطريق.
- مقدّر سرعة يعتمد على المسافة المترية والزمن، ويعلّم القياس غير الصالح إذا لم يكن توقيت المصدر موثوقاً.
- تحليل عبور الخطوط الافتراضية ومراقبة المناطق والتسكع.
- قاعدة أولية لحدث تجاوز حد السرعة، بشرط صلاحية المعايرة والتوقيت.
- مصدر فيديو OpenCV اختياري ومحرك تتبع Ultralytics اختياري.
- مخزن أحداث SQLite دائم وواجهة API أولية.
- اختبارات للوحدات وGitHub Actions.

**غير منجز بعد:** إدارة أسطول كاميرات حقيقي، بث WebRTC/WebSocket حي إلى لوحة المتصفح، واجهة SOC النهائية، ربط عدة كاميرات جغرافياً/زمنياً، ANPR/OCR، نماذج اكتشاف الحوادث المدربة، واختبارات ميدانية للسرعة والدقة. لا توجد أوزان نماذج مرفقة؛ يجب اختيارها وفحص ترخيصها وحجمها قبل التشغيل.

## التثبيت والتشغيل

يتطلب Python 3.12 أو 3.13.

~~~bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell
.venv/Scripts/Activate.ps1

python -m pip install --upgrade pip
pip install -e ".[dev]"
~~~

لإضافة دعم الفيديو والكشف اختياريًا:

~~~bash
pip install -e ".[vision,dev]"
~~~

شغّل API:

~~~bash
uvicorn traffic_surveillance.api.app:app --reload
~~~

- التوثيق: http://127.0.0.1:8000/docs
- الصحة: http://127.0.0.1:8000/healthz
- الأحداث: http://127.0.0.1:8000/api/v1/events

## متطلبات الدقة

لا يُحسب قياس سرعة صالح لمخالفة إلا إذا اجتمعت:
1. معايرة أرضية مترية صالحة لهذه الكاميرا مع خطأ إعادة إسقاط معروف.
2. نقطة تمثيل مناسبة للمركبة، عادةً نقطة ملامسة الإطار السفلي للطريق لا مركز الصندوق.
3. Track مستقر للسيارة مع تقليل تبديل الهويات.
4. مصدر توقيت دقيق للإطارات، لا مجرد وقت وصول الحزمة إلى الهاتف/الخادم.
5. تحقق ميداني مستقل مقابل مرجع سرعة معروف، مع تسجيل الخطأ والانحياز.

## الأمان والخصوصية

- تُربط فقط الكاميرات والمواقع التي يملكها المستخدم أو لديه تصريح بإدارتها.
- لا توجد مراقبة خفية أو تجاوز لوسائل الوصول.
- لا يجري التعرف البيومتري على الوجوه في هذا النطاق الافتراضي.
- أي مطابقة بين كاميرات أو قراءة لوحة مركبة ميزة اختيارية تخضع للصلاحيات والاحتفاظ واللوائح المحلية.
- الإنذارات ذات الأثر العالي تبقى خاضعة لمراجعة بشرية.

## ملاحظة الترخيص

Ultralytics وبعض نماذجها لها شروط ترخيص قد تتطلب التزامات AGPL أو ترخيصاً تجارياً بحسب طريقة الاستخدام والتوزيع. لذلك تكاملها اختياري ولا ندمج الأوزان أو نوزعها قبل مراجعة الترخيص. NVIDIA DeepStream يتطلب عتاداً وبرمجيات NVIDIA مدعومة؛ لن يكون شرطاً لتشغيل نواة CPU العامة.
