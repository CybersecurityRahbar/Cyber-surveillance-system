# نظام المراقبة السيبرانية المتقدم

**Cyber Surveillance System** مشروع لبناء منصة دفاعية مركزية لمراقبة أمن الشبكات والأجهزة والخدمات، وتحليل الأحداث، واكتشاف السلوكيات المشبوهة، وربطها زمنياً، وتقديمها للمحلل ضمن واجهة تحقيق موحدة.

> هذا مستودع جديد وليس امتداداً تقنياً لتطبيق مراقبة المرور Android. تمت مراجعة المشروع السابق للاستفادة من دروس المعمارية والاختبار والتوثيق فقط. نطاق هذا المستودع هو المراقبة الأمنية الدفاعية للأنظمة التي نملكها أو لدينا تصريح صريح بمراقبتها.

## ما تم بناؤه الآن

- مشروع Python منظم باستخدام FastAPI وPydantic.
- نموذج موحد للأحداث الأمنية مع الوقت ومصدر الحدث والمضيف والحساب وعناوين الشبكة.
- طبقة تطبيع أولية تقبل الحقول الشائعة في السجلات وتحتفظ بالحدث الخام للتدقيق.
- واجهة REST لاستقبال دفعات أحداث، واستعراض الأحداث والتنبيهات وحالة الخدمة.
- محرك كشف أولي لاكتشاف موجة فشل تسجيل الدخول ضمن نافذة زمنية، مع التعامل مع الأحداث المتأخرة ومنع إعادة تنبيه الحدث نفسه.
- حماية اختيارية بمفتاح API، وإجبارها عند استخدام وضع الإنتاج أو الربط على عنوان غير loopback.
- اختبارات للوحدات وواجهات API وWorkflow أولي في GitHub Actions.

**حدود الإصدار الأول:** التخزين الحالي في الذاكرة فقط ويُمسح عند إعادة تشغيل الخدمة. لا يوجد بعد عميل Endpoint، أو التقاط حزم، أو محلل PCAP، أو تخزين دائم، أو محرك Sigma، أو واجهة SOC النهائية. هذه أمور مخططة بمراحل منفصلة ولا ندّعي أنها جاهزة.

## تشغيل نسخة التطوير

يتطلب Python 3.12 أو 3.13.

~~~bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell
.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -e ".[dev]"
uvicorn cyber_surveillance.api.app:app --reload
~~~

افتح http://127.0.0.1:8000/docs لتجربة API التوثيقية، و http://127.0.0.1:8000/healthz لفحص الخدمة.

### إرسال حدث اختباري

~~~bash
curl -X POST "http://127.0.0.1:8000/api/v1/events/ingest" \
  -H "Content-Type: application/json" \
  -d '{
    "sensor_id": "lab-auth-01",
    "source_type": "syslog",
    "events": [{
      "event_id": "demo-auth-001",
      "@timestamp": "2026-11-01T10:00:00Z",
      "event": {"category": "authentication", "action": "user-login", "outcome": "failure"},
      "user": {"name": "analyst"},
      "source": {"ip": "192.0.2.10"},
      "host": {"name": "lab-server"}
    }]
  }'
~~~

أرسل خمسة أحداث فشل بالمستخدم وعنوان المصدر نفسيهما ضمن خمس دقائق لتجربة قاعدة الكشف الأولية. العناوين من نطاق TEST-NET التوثيقي وليست أهدافاً حقيقية.

## مبادئ لا نتنازل عنها

1. لا مراقبة خفية ولا جمع بيانات من أنظمة لا نملكها أو لا نملك تصريحاً بمراقبتها.
2. لا تنفيذ تلقائي لإجراءات مدمرة أو حظر أو عزل جهاز دون سياسة معتمدة ومراجعة بشرية.
3. كل تنبيه يجب أن يوضح لماذا أُنشئ، والأحداث التي دعمته، والقاعدة وإصدارها ومصدر البيانات.
4. لا نخلط بين غياب البيانات وسلامة النظام؛ يجب قياس صحة المستشعرات وفجوات الجمع.
5. التوقيت، ومصدر الحدث، ومعرفه، وسلسلة الحيازة، والتكرار، والتأخير أمور أساسية.
6. لا نضيف قاعدة بيانات أو وسيط رسائل ضخم قبل قياس الحاجة؛ نبدأ بوحدات قابلة للاستبدال ثم نوسعها.
7. كل ميزة تُسجل على أنها منفذة فقط عند وجود مسار عمل واختبار يثبتها.
