# نظام المراقبة المرورية والأمنية الذكي

**Cyber Surveillance System** منصة مركزية مبنية بـ Python والرؤية الحاسوبية لمراقبة الطرق والمناطق والمنشآت عبر الكاميرات، وتحويل الفيديو إلى تحليلات وأحداث قابلة للفهم والتحقيق.

> هذا المشروع ليس SIEM ولا برنامج حماية أجهزة. نطاقه هو المراقبة المرئية المرورية والأمنية بالكاميرات، مع تحليلات حركة المركبات والأشخاص والأحداث الميدانية.

## المختبر — جرّب النظام دون كاميرا حقيقية

قسم المختبر يتيح اختبار كاميرا واحدة قبل بناء أسطول الكاميرات:

- ارفع فيديو من جهازك بصيغ MP4/MOV/MKV/AVI/WEBM وغيرها.
- شغّل YOLO26n مع ByteTrack أو BoT-SORT أو OC-SORT أو Deep OC-SORT أو FastTracker أو TrackTrack.
- في الفيديوهات المحلية: شاهد الإطارات المعالجة عبر MJPEG واحفظ MP4 الناتج. لوحة HUD داخل الفيديو اختيارية.
- في نمط الرصد الحي: استخدم ملف معالجة منخفض التأخير، مع ByteTrack افتراضياً، وإيقاف ترميز MP4 أثناء الجلسة لتقليل الحمل، وتحديث قائمة الهويات النشطة وتقاريرها لحظياً.
- يعرض النظام FPS استقبال الكاميرا منفصلاً عن FPS التحليل، وزمن الاستدلال وعمر الإطار وعدد الإطارات المستلمة والمستبدلة.
- تظهر هويات الأجسام النشطة خارج شاشة الرادار، وتُرتب حسب آخر ظهور. تظهر أحداث عبور الخط في مركز الأحداث أثناء الجلسة.
- يمكن تشغيل مصدر حي عبر RTSP أو كاميرا الخادم أو تطبيق Android عبر WSS/JPEG. جلسات الهاتف مستمرة حتى الإيقاف اليدوي افتراضياً.

## التثبيت

يتطلب Python 3.12 أو 3.13.

~~~bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell
.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -e ".[video,vision]"
~~~

يفصل المشروع دعم الفيديو عن نموذج الذكاء الاصطناعي:
- video: PyAV/FFmpeg لفك ترميز الفيديو.
- vision: Ultralytics YOLO للكشف والتتبع، ويتضمن اعتماد OpenCV المستخدم في الرسم والمعالجة.
- dev وtest-video: أدوات الاختبار والفحص، ولا يحتاجها تشغيل المنصة على Colab.

يهيئ المختبر نموذج YOLO26n عند أول عملية تحليل؛ قد يحتاج اتصالاً بالإنترنت لتنزيل الأوزان أول مرة. تُحفظ الأوزان في مخزن Ultralytics المحلي ولا تُرفع إلى GitHub.

### تقارير هويات التتبع وسمات المركبات

- تحفظ كل جلسة مكتملة في SQLite ضمن `lab_sessions`، ويحفظ كل Track في `lab_tracks` مع نوع الجسم والصنف وأول/آخر ظهور وعدد الإطارات والثقة وصناديق البداية/النهاية ونقاط المسار وعبور خط العد.
- يحاول النظام تقدير لون المركبة من عدة إطارات باستخدام HSV؛ النتيجة تقريبية وقد تتأثر بالظل والانعكاس والإضاءة. تُحفظ درجة الثقة وعدد العينات، ولا ينبغي اعتبار اللون وحده دليلاً حاسماً.
- لا يستطيع YOLO26n العام تحديد الماركة والطراز. توجد وصلة اختيارية لمصنف Ultralytics من نوع `classify` عبر المتغير `TRAFFIC_SURVEILLANCE_VEHICLE_MODEL_PATH`. يجب أن تكون أوزانه مدرّبة فعلياً على أسماء ماركات/طرازات مناسبة، وأن يكون ترخيص بيانات التدريب والأوزان ملائماً للاستخدام. لا تتضمن المستودع أوزاناً لمصنف هايلوكس/توسان/G-Class.
- تصدّر واجهة المختبر تقرير الجلسة ومسارات الأجسام إلى JSON. واجهات API للتقارير: `/api/v1/lab/reports` و`/api/v1/lab/reports/{session_id}` و`/api/v1/lab/reports/{session_id}/tracks`.


## بث الهاتف المباشر إلى النظام

يوجد تطبيق Android فعلي في `android-phone-camera` يستخدم CameraX ويرسل إطارات JPEG الثنائية عبر WebSocket آمن `WSS` إلى:
`/api/v1/phone/stream/{camera_id}`.

### طريقة الربط
1. شغّل دفتر Colab واختر GPU إن كان متاحاً، واترك خلية الإشراف النهائية تعمل.
2. انسخ رابط Cloudflare HTTPS الحالي وضعه في حقل Base URL في التطبيق فقط؛ لا تضف `/lab` أو مسار API.
3. استخدم Camera ID مثل `road-01`، وأدخل مفتاح API نفسه الذي أدخلته في Colab.
4. ابدأ البث في التطبيق، ثم في المختبر اختر Live واكتب `phone-camera:road-01` كمصدر.
5. أوقف الجلسة من زر إيقاف المعالجة في المختبر، وأوقف إرسال الهاتف عند الانتهاء.

يعمل الهاتف والمتصفح من شبكتين مختلفتين ما دام النفق العام نشطاً. يتطلب التطبيق حالياً بقاء Activity ظاهرة في المقدمة؛ لا يدعم بعد خدمة foreground مستمرة ولا H.264/WebRTC. التطبيق يعرض معاينة أفقية، تمرير الإعدادات، وزر ملء الشاشة. يجب عدم مشاركة API key أو رابط النفق علناً.

### مسار الرصد الحي
- يحتفظ الخادم بأحدث إطار فقط، ويستبدل الإطارات القديمة عند ازدحام المعالجة بدلاً من بناء طابور يزيد التأخير.
- ملف الرصد الحي يستخدم YOLO26n بحجم استدلال 384، وByteTrack، وحد معالجة 640px/30 كشفاً، ويوقف كتابة MP4 أثناء الجلسة.
- تُحدّث قائمة هويات التتبع النشطة والجدول المباشر مع كل إطار محلل؛ لا ينتظر التطبيق انتهاء الجلسة لعرض هذه البيانات.
- يعرض مركز العمليات معدل الإطارات الواردة من الهاتف منفصلاً عن معدل استدلال YOLO، وزمن الاستدلال وعمر آخر إطار وعدد الإطارات التي استبدلها مخزن latest-frame.
- لا يعني حد استقبال 10 FPS أن الاستدلال يحقق 10 FPS تلقائياً. المعدل النهائي يعتمد على GPU/CPU والهاتف والشبكة. لا يعتمد النظام ميدانياً قبل اختبار معدل التحليل والتأخر على العتاد المستهدف.

### المسار المستقبلي عالي الكفاءة
الهدف التالي هو تقييم H.264 hardware encode وWebRTC/WHIP إلى MediaMTX، ثم تغذية محرك Python بمسار وسائط مستقر. هذا ليس بروتوكول التطبيق الحالي بعد. كما أن Video Wall حقيقي متعدد الكاميرات ومعايرة أرضية مترية كاملة ما زالا ضمن مراحل لاحقة. تفاصيل التصميم والقيود في docs/PHONE_CAMERA_STREAMING.md.

## نطاق الكشف الحالي وحدوده

نموذج YOLO26n العام يتعرف على فئات COCO مثل car وtruck وbus وmotorcycle وbicycle وperson. لكنه ليس نظاماً عاماً لكل المخالفات.

- **تعداد المركبات:** يعرض عدد هويات التتبع الفريدة وعدد عبور خط العد كمؤشرين مختلفين. انقطاع Track ID أو ID switch قد يؤثر على العدد.
- **سرعة المركبة:** تحتاج معايرة أرضية مترية مستقلة لهذه الكاميرا، مع نقاط طريق مقاسة وتوقيت موثوق وتحقق ميداني. المختبر الحالي لا يختلق أرقام سرعة.
- **قراءة اللوحات:** تحتاج كاشف لوحات متخصصاً ثم OCR مهيأً لشكل اللوحات المحلية، بما في ذلك الحروف والأرقام العربية/اللاتينية. ليست موجودة في YOLO26n العام.
- **الإنفاذ:** نتائج العدّ والتتبع في المختبر تجريبية وليست دليلاً رسمياً أو مخالفة مؤكدة.
- **المراقبة متعددة الكاميرات:** لكل كاميرا حالة Tracker مستقلة؛ ربط الهوية بين الكاميرات مرحلة لاحقة.
